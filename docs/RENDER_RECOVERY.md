# Checked render attempts and publication recovery

Full verification awards E04 and E06 extended for bounded recovery and the documented failure-injection cases. [Editing-session migration](PORTABLE_PROJECTS.md) retains its separate criteria.

`render.start` accepts optional `render.retry: {"max_attempts": 2}`. The number includes the first attempt and must be 1–3. Omission retains one attempt. Only `TOOL_FAILED`, `TOOL_TIMEOUT` and an interrupted worker are eligible to retry. Cancellation, changed media/tools, invalid inputs, publication conflicts and other errors stop the job. Retries begin a fresh encode and remain bounded by the original queue limits: one active render and 32 queued/running jobs per root. There is no background service or mid-codec resume.

Transient failures retry while the worker drains its queue. After an abrupt worker exit, `job.status` reconciles durable state without launching a process; `job.resume` starts a worker for queued work. The same submission ID and identical arguments still return the original ticket. Changing the attempt policy under that ID rejects. Completed, cancelled and exhausted jobs are never replayed by `job.resume`.

Submission saves the snapshot and exact selected tool paths and hashes. Each attempt checks the tool contents. The first fully validated render plan saves source paths, hashes and frame/sample counts; subsequent attempts must match that manifest. Source files remain unchanged. This first-plan boundary does not pin files before submission or rescue sources that change during initial inspection. Existing bound asset identities retain their earlier protection.

`job.status` includes `attempts.current`, `attempts.maximum` and ordered attempt history with terminal status and error. Attempt progress restarts at zero. A retried job retains earlier failures in history after completion. The first partial keeps its existing filename; later attempts use a distinct `.attempt-<number>.partial.mkv` suffix. Normal failure removes its own partial. Crash partials remain for inspection and are never used as source data for a retry or silently deleted.

Before publication the queue commits the validated receipt, its checksum and the exact request/output/attempt identity. A second writer transaction serializes the final cancellation check with no-overwrite publication and completion. If a worker stops after publishing but before recording completion, recovery checks the durable receipt and actual output hash. An exact match completes the job without encoding again. A missing output may retry only under the saved policy; an altered output or corrupt receipt fails and retains all existing files. A completed output can win a simultaneous cancellation. Recognition is content-based; it does not establish the identity of another process that may have written identical bytes.

The queue database migrates its own schema from version 1 to 2 in a transaction, preserving requests, ticket identities, prior results and statuses. Earlier jobs retain a one-attempt policy. Historical nonqueued rows are represented as one prior attempt because the earlier schema had no attempt log. An unsuccessful migration rolls back schema changes and preserves existing rows. This is distinct from the version-1 editing-session database and earns no project migration checkpoint.

The hidden Windows launcher explicitly disables caller-handle inheritance. This prevents a background worker from keeping the submitting CLI's output pipe open after the ticket has returned. Windows process and thread handles are closed after launch; the worker retains its existing lifetime scope for media subprocesses. The implementation uses the documented [process creation interface](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), with no new dependency or copied implementation.

Focused acceptance compares **32 real rendered frames and 61,440 stereo sample frames** against original independent RGB/PCM slices. Four groups cover successful retry, exact ticket replay, source mutation between attempts, three-attempt exhaustion, actual worker/tree termination, all 32 queue slots, cancellation, typed MCP and paths containing spaces and Unicode. Six substantive Rust checks stop child processes at the two publication boundaries, reject altered/corrupt publication, retain attempt/source history and exercise successful/rolled-back queue migration. The crash-child helper is excluded from scored checks. Existing renderer and MCP/job regressions are required separately.

The storage profile remains local Windows filesystems with working locks and hard links. Power-loss durability, remote/network filesystems, hostile concurrent file mutation, arbitrary orphan cleanup, multi-root scheduling and job-history pruning are not claimed by this bounded process-crash acceptance.

## Render failure injection

The original `tests/render_failures.py` fixture compiles `tests/render_failure_tool.rs` into an external test directory. This adapter passes real encoder bytes through an original bounded writer that injects Windows `ERROR_DISK_FULL` after 8,192 bytes. The evidence records the injected OS error, byte count and actual encoded partial hash. No physical volume is filled, and this synthetic write fault does not establish behavior for every filesystem or hardware failure. There is no injection switch in the production engine.

Synchronous failures and three exhausted queued attempts remove their own partials without publishing an output. A fresh attempt after one fault produces exact decoded RGB/PCM and preserves the first failure in history. The encoder's failed exit remains `TOOL_FAILED`; the engine does not infer a reliable disk-space diagnosis from arbitrary tool diagnostics. The saved retry policy applies and is never unbounded.

Additional checks mutate an original synthetic source after a complete encode and confirm that both synchronous and queued publication reject with `MEDIA_CHANGED`; the queued job does not retry. Another case terminates the actual worker while real encoded bytes are in its partial, confirms the encoder process tree exits, then verifies a successful new attempt while preserving the crash partial. Existing output and all synthetic sources are checked throughout; the fixture explicitly restores its own source mutation.

These three groups independently compare 128 decoded frames and 245,760 stereo sample frames. Together with the real publication-boundary crash checks, they satisfy the prepared E06 extended evidence assignment when the stable full suite passes. Migration disk-full checks remain separate history evidence.
